# เช็กลิสต์ก่อนเปิดขายจริง

เรียงตามความสำคัญ — ทำข้อบนก่อน **ห้ามข้ามข้อที่ติด 🔴** (ผลกระทบคือเงิน/ข้อมูลลูกค้า/กฎหมาย)
ติ๊กได้เมื่อ "ทำและตรวจแล้วจริง" ไม่ใช่เมื่อ "ตั้งใจจะทำ"

## 🔴 ต้องทำก่อนรับเงินจริง

- [ ] **สร้าง secret ใหม่ทั้งหมดสำหรับ production** (อย่าใช้ค่าจากเครื่องพัฒนา):
  `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` สำหรับ `JWT_SECRET` และ `KEY_ENCRYPTION_SECRET` (คนละค่ากัน)
- [ ] **สำรอง `.env` (โดยเฉพาะ `KEY_ENCRYPTION_SECRET`) ไว้ที่ปลอดภัยนอกเซิร์ฟเวอร์** — ทำหายหรือเปลี่ยนค่า = โค้ดเกมที่เข้ารหัสไว้ทั้งหมดใช้ไม่ได้ ไม่มีทางกู้
- [ ] **Stripe Live:** เปิดใช้งานบัญชี (ยืนยันตัวตนธุรกิจ/บัญชีธนาคาร) → ใส่ `sk_live_…` / `pk_live_…`; เปิด PromptPay ใน Live mode (อาจต้องรอ Stripe อนุมัติ)
- [ ] **Stripe Webhook บนโดเมนจริง:** Add endpoint `https://โดเมนคุณ/api/webhooks/stripe` ด้วย event ตามรายการใน README → คัดลอก Signing secret (`whsec_…`) ของ endpoint **Live** (คนละค่ากับโหมดทดสอบ/Stripe CLI) ใส่ `STRIPE_WEBHOOK_SECRET`
- [ ] **ทดสอบซื้อจริงหนึ่งรอบด้วยยอดต่ำสุด** (บัตรและ PromptPay) แล้วตรวจ: ออเดอร์เป็น paid เอง, ได้โค้ด, อีเมลถึง, ใบเสร็จ PDF ถูกต้อง, แล้ว **คืนเงินจากหลังบ้าน** ดูว่าเงินกลับเข้าบัตรและโค้ดถูกเพิกถอน
- [ ] **นำเข้าโค้ดเกมจริง** (CSV) ผ่านหลังบ้าน และ **ลบ/ซ่อนเกมตัวอย่างและโค้ดปลอม `FAKE-…`** ทั้งหมด (production ไม่ seed ให้อยู่แล้ว แต่ถ้าเคยรัน seed บน DB เดียวกันต้องล้าง)
- [ ] **ตั้ง SMTP จริง** + SPF/DKIM/DMARC ของโดเมนผู้ส่ง → ทดสอบว่าอีเมลยืนยัน/ลืมรหัสผ่าน/ส่งโค้ดเข้ากล่องจดหมายหลัก (ไม่ใช่สแปม)
- [ ] **สร้างแอดมินจริง** (`make-admin`) ด้วยรหัสผ่านยาว ไม่ซ้ำ, **ตั้ง 2FA และเก็บรหัสกู้คืนไว้นอกเครื่อง** (มี admin อย่างน้อย 2 คน เผื่อคนหนึ่งทำโทรศัพท์หาย); ตรวจว่าไม่มีบัญชีทดสอบ (`buyer@…`, `staff1@…` ฯลฯ) เหลืออยู่ใน DB production
- [ ] `NODE_ENV=production npm run check:env` ผ่านโดยไม่มี error และอ่านคำเตือนทุกข้อ
- [ ] **HTTPS ใช้งานได้จริง** + `APP_URL=https://…` + `TRUST_PROXY=1` (ถ้าอยู่หลัง proxy) → เปิดเว็บแล้วตรวจ header `Strict-Transport-Security` และไม่มี mixed content
- [ ] **ข้อมูลอยู่บนดิสก์ถาวร** (Docker volume / Render persistent disk ที่ `/app/data` — **ไม่ใช่ plan ฟรีของ Render**) และตั้ง `REQUIRE_EXISTING_DB=1` หลังติดตั้งครั้งแรก → ทดสอบโดย redeploy/restart แล้วตรวจว่าออเดอร์/ผู้ใช้เดิมยังอยู่
- [ ] **ตั้งสำรองข้อมูลอัตโนมัติ + คัดลอกออกนอกเครื่อง + ทดสอบกู้คืนอย่างน้อยหนึ่งครั้ง** (`npm run backup` / `npm run restore`)

## 🟠 ต้องให้ผู้เชี่ยวชาญตรวจก่อนเปิดจริง (ระบบนี้ไม่ใช่คำปรึกษาทางกฎหมาย/บัญชี)

- [ ] **นักบัญชี/ที่ปรึกษาภาษี:** ตรวจรูปแบบใบเสร็จ PDF — ปัจจุบันเป็น *ใบกำกับภาษีอย่างย่อ* (ราคารวม VAT 7% แยกบรรทัดให้, ไม่มีชื่อ/เลขผู้เสียภาษีผู้ซื้อ, เลขที่รัน `INV-ปี-######`) ว่าตรงตามข้อกำหนดของธุรกิจคุณหรือไม่ (จดทะเบียน VAT หรือยัง, ต้องออกใบกำกับภาษีเต็มรูปหรือ e-Tax Invoice หรือไม่) และใส่ `SHOP_NAME/ADDRESS/TAX_ID` จริง
- [ ] **ทนายความ:** หน้า `/privacy` (นโยบายความเป็นส่วนตัว), `/terms` (ข้อกำหนดการใช้งาน), `/refund-policy` (การคืนเงิน) ในโปรเจกต์เป็น **ตัวอย่างร่างเพื่อเริ่มต้นเท่านั้น** (มีป้ายระบุในหน้า) — ต้องแก้ให้ตรงธุรกิจจริง ชื่อนิติบุคคล ช่องทางติดต่อ และให้ผู้เชี่ยวชาญตรวจ แล้วลบป้าย "ตัวอย่าง" ออก
- [ ] **PDPA:** ระบุวัตถุประสงค์/ฐานทางกฎหมายของข้อมูลที่เก็บ (ชื่อ อีเมล ประวัติสั่งซื้อ ที่อยู่ IP ใน audit log), ระยะเวลาเก็บ, สิทธิ์ของเจ้าของข้อมูล (ขอดู/แก้/ลบ) และช่องทางใช้สิทธิ์, ผู้ประมวลผลภายนอก (Stripe, ผู้ให้บริการอีเมล, โฮสติ้ง) — **ระบบยังไม่มีหน้า "ลบบัญชี/ส่งออกข้อมูล" อัตโนมัติ** ต้องมีขั้นตอนทำด้วยมือหรือพัฒนาเพิ่ม
- [ ] **คุกกี้:** ตอนนี้ใช้เฉพาะคุกกี้ที่จำเป็นต่อการทำงาน (`token`, `admin_token`, `csrf`) และ localStorage/sessionStorage เก็บภาษา ตะกร้าชั่วคราว เกมที่เพิ่งดู คำค้นล่าสุด และสถานะระหว่างสั่งซื้อ (รายการครบอยู่ใน `public/privacy.html` และมีเทส `tests/privacy.test.js` เทียบกับโค้ดทุกครั้ง) ไม่มีคุกกี้โฆษณา/วิเคราะห์ จึง **ยังไม่มีแบนเนอร์ขอความยินยอม** — ให้ผู้เชี่ยวชาญยืนยันว่าเพียงพอ และต้องเพิ่มแบนเนอร์ทันทีหากคุณเพิ่ม Google Analytics / Facebook Pixel / สคริปต์ภายนอกอื่น (และต้องปรับ CSP ใน `server/app.js` ให้อนุญาตโดเมนนั้น)
- [ ] **เงื่อนไขการขายโค้ดดิจิทัล/สิทธิ์บอกเลิกของผู้บริโภค:** นโยบายคืนเงินของคุณต้องสอดคล้องกฎหมายคุ้มครองผู้บริโภคและข้อตกลงกับผู้จัดจำหน่ายเกม (ใบอนุญาตขายโค้ดต่อ/โค้ดมาจากแหล่งที่ถูกต้อง)
- [ ] **ข้อกำหนดของ Stripe:** รายการสินค้าที่ขายต้องไม่ขัดนโยบาย Stripe (Restricted businesses) — บัญชีอาจถูกระงับหากขายโค้ดที่มาไม่ชอบ

## 🟡 ควรทำ

- [ ] **ทดสอบบนมือถือจริง** (iOS Safari, Android Chrome) — ที่ผ่านมาทดสอบด้วย viewport จำลองใน Chromium เท่านั้น (Firefox ยังไม่ได้ทดสอบ)
- [ ] **ทดสอบ Docker build จริง** บนเครื่อง/CI: `docker compose build` แล้ว `docker compose up -d` ตรวจ `docker compose ps` ว่า `healthy`, ล็อกอินแอดมิน, อัปโหลดรูป (ตรวจสิทธิ์เขียนโฟลเดอร์ `/app/data`), เปิดหน้าเกมแล้วรูป OG แสดงตัวอักษรไทยถูก
- [ ] **อัปเดตเวอร์ชันและตรวจช่องโหว่เป็นระยะ:** `npm audit --omit=dev` และอัปเดต base image (`node:24-bookworm-slim`) ทุกเดือน
- [ ] ตั้ง **การเฝ้าระวัง**: uptime monitor ชี้ `/healthz`, แจ้งเตือนเมื่อดิสก์เต็ม, ตรวจแดชบอร์ด "การแจ้งเตือนแอดมิน" ทุกวัน (คืนเงินล้มเหลว, อีเมลส่งไม่ออก, โค้ดใกล้หมด)
- [ ] ตั้งเกณฑ์สต็อกต่ำของแต่ละเกม และมีแผนเติมโค้ด (ลูกค้าจ่ายแล้วโค้ดหมด = คืนเงินอัตโนมัติ แต่เสียความเชื่อมั่น)
- [ ] จำกัดการเข้าถึง `/admin` เพิ่มเติมถ้าทำได้ (IP allowlist ที่ proxy, VPN) และเปิด 2FA ที่บัญชี Stripe/โฮสติ้ง/อีเมลโดเมน (**ระบบนี้ยังไม่มี 2FA สำหรับแอดมินใน /admin**)
- [ ] ตรวจ `robots.txt` / `sitemap.xml` บนโดเมนจริง และส่ง sitemap ให้ Google Search Console; ตรวจรูป OG ด้วยเครื่องมือ debugger ของ Facebook/LINE
- [ ] ตรวจ Lighthouse บนเว็บจริงหลังมี CDN/proxy (ผลที่วัดไว้เป็นการวัดในเครื่องพัฒนา)
- [ ] ซ้อมแผนฉุกเฉิน: ถ้าสงสัยว่า `JWT_SECRET` รั่ว → เปลี่ยนแล้วทุกคนถูกบังคับล็อกอินใหม่ (ปลอดภัย); ถ้า `KEY_ENCRYPTION_SECRET` รั่ว → ต้องออกโค้ดใหม่/เข้ารหัสใหม่ (ไม่มีสคริปต์ rotate ให้ — ต้องพัฒนาเพิ่ม)

## ข้อจำกัดที่ทราบ (ไม่ใช่บั๊ก แต่ควรรู้)

- รองรับคืนเงิน **เต็มจำนวน** เท่านั้น (คืนบางส่วนจาก Stripe Dashboard ระบบบันทึกยอดและแจ้งเตือน แต่ออเดอร์ยังเป็น paid และโค้ดยังใช้ได้)
- ฐานข้อมูลเป็น SQLite ไฟล์เดียว: เหมาะกับร้านขนาดเล็ก–กลาง รันได้ทีละ instance เดียว (ไม่ scale แนวนอน); ถ้าโตเกินนี้ต้องย้ายไป PostgreSQL (SQL เขียนแบบพกพาไว้แล้วแต่ยังไม่ได้ทำ migration จริง)
- ใบเสร็จเป็น "ใบกำกับภาษีอย่างย่อ" ไม่ใช่ e-Tax Invoice
- ไม่มีระบบกู้บัญชีแอดมินเมื่อลืมรหัสผ่านนอกจากกระบวนการลืมรหัสผ่านปกติหรือใช้ CLI บนเซิร์ฟเวอร์
